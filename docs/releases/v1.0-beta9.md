# Mhirex 1.0-beta9 (pre-release)

This is a **pre-release** build for testing, not a statement of production readiness or licence
compliance.

## What is in this build

- **Gujarati (ગુજરાતી) translation added.** Mhirex now ships in 18 languages. Gujarati covers 198
  strings. The 20 profile and sign-in strings added in `v1.0-beta8` fall back to English in
  **every** non-English language, not only Gujarati — none of the 17 translations carry them yet.
  Gujarati was contributed externally and has not been reviewed by a native speaker. Please report
  anything that reads wrong.
- **New app logo** on the About screen, the first-launch sign-in prompt, and the startup welcome
  screen.
- **The home-screen launcher icon is unchanged** and still uses the previous logo. Switching it was
  prepared and then reverted on request, because the previous icon is the one Mhirex has always
  shipped. See the themed-icon item under limitations.
- **Sign-in no longer dead-ends with "No Google account is available on this device".** `v1.0-beta8`
  used Credential Manager's bottom-sheet flow (`GetGoogleIdOption`) for a button-triggered sign-in.
  That flow only offers accounts which have already granted access, and per Google's own
  troubleshooting notes it does not appear at all when the account's *Sign in with Google* prompts are
  turned off — so users got an error with no chooser to pick from. Sign-in now runs Google's
  documented button flow (`GetSignInWithGoogleOption`), which always presents the full account
  chooser. The bottom sheet is still tried first so a returning user gets one-tap sign-in,
  escalating to the button flow when it declines.
- **Sign-in no longer rejects every successful login.** The response was type-checked with
  `is GoogleIdTokenCredential`, which is never true for the `CustomCredential` that `getCredential`
  actually returns, so a real sign-in would have been reported as an unexpected credential type. Both
  Google ID token credential subtypes are now accepted. This bug was masked behind the "no account"
  failure above.
- **Sign-out now clears Google's credential state**, so a user who signs out can actually switch
  accounts. Without this, the credential provider can keep the previous session active and only offer
  that one account next time.
- **A corrupt or undecodable cached avatar now falls back to initials.** If the cached avatar file
  existed but failed to decode, the profile card left the photo frame visible over an empty
  rectangle instead of falling back to the initials, which is the opposite of what that view is for.
- **The app now links to the Mhirex website** (https://mhirex.vercel.app) from the About screen.
- Optional **Sign in with Google** profile remains optional. Nothing in the editor is gated behind
  an account, and there is a single `signIn(` call site, on the button's click handler, so the app
  never prompts for an account on its own.
- Release APKs are signed with the project release key.

## Sign-in: what you must do before it can work

Google matches the calling app by **package name plus signing-certificate SHA-1**. The Firebase
project `mhirex-5888` has the Web OAuth client
`444731751675-28prvlfdjuhshvn0shmebbpb02e03not.apps.googleusercontent.com` registered for
`com.mhirex.editor`, but against the **release** certificate only.

So any locally built **debug** APK is rejected by Google with:

```
Auth.Api.Credentials: [8] Unknown error [status=UNREGISTERED_ON_API_CONSOLE]
Auth.Api.Credentials: [16] Account reauth failed
```

This was found by running the flow on an emulator and reading `adb logcat -s Auth.Api.Credentials`.
It is not a defect in the app's sign-in code. To make debug builds work, add the debug keystore
fingerprints to the OAuth client in the Google Cloud console. The device must also have a real Google
account added; Credential Manager cannot sign anyone in who is not there.

Note that Play Services reports this failure to the app as a *cancellation*, identical to the user
dismissing the chooser, so **the app shows nothing at all** when it happens. That is deliberate: a
user with a working account who dismisses the chooser would otherwise get a spurious error dialog, and
Credential Manager provides no way to tell the two cases apart. `GoogleSignInManager` logs the
ambiguity and the exact `adb logcat` incantation to diagnose it.

## Known limitations in this build

- **Sign-in is now verified end to end, but sign-out is not.** A completed sign-in was observed on an
  API 36 emulator: Google's chooser completed, the profile was stored locally
  (`profile_signed_in`, display name, email, photo URL), and the avatar was downloaded and cached
  (`cache/user_avatar.jpg`). No ID token is persisted. The earlier
  `UNREGISTERED_ON_API_CONSOLE` failure was an environment problem, not a code defect: the device had
  no screen lock registered, so account reauth could not complete. **Sign-out has not been
  exercised**, so `clearCredentialState()` and avatar deletion are still untested. Sign-out is the
  path that removes a personal photo from disk, so try it before relying on it.
- **Themed (monochrome) app icons do not work**, and the `v1.0-beta8` changelog line claiming
  "Android 13+ monochrome themed app icon support" is not accurate. `AndroidManifest.xml` points
  `android:icon` at the flat raster `@mipmap/logo`, so `mipmap-anydpi-v26/ic_launcher.xml` never
  resolves and its `<monochrome>` layer is dead code. Corrected adaptive-icon layers are committed
  and ready; enabling them is a one-line manifest change.
- The new mark has **not** been reviewed by eye by a designer. Contrast was verified numerically
  (worst case 8.19:1 on the About halo, 21:1 on the sign-in badge, well past the 3:1 WCAG threshold
  for non-text), but nobody has looked at whether it reads well.
- Device testing has only been run on an **API 36** emulator. API 29, 33 and 34 are not yet verified.
- The bundled `filter_preview_*.jpg` and `trans_preview_*.webp` assets do not yet have documented
  provenance.
- `mipmap-nodpi/logo.png` is still the launcher icon, so it remains referenced. The Android Studio
  template `ic_launcher_background` assets (a `#FFFFFF` colour and a green grid vector) are
  unreferenced leftovers and were left in place rather than deleted.

## Licence and source availability — still incomplete

Unchanged from `v1.0-beta8`. Mhirex bundles `ffmpeg-kit-full-gpl`, which is licensed under GPL-3.0.
**The GPL disclosure work is not complete.** The in-app AboutLibraries entry, the packaged GPL
licence text and the corresponding-source offer still need to be added.

This release therefore **does not claim to be GPL-compliant**, and must not be represented as
satisfying GPL distribution obligations. Those obligations need to be completed before a public or
Play Store distribution. LibreCuts/MIT attribution from the upstream project is retained in the app
and repository.
