# Mhirex 1.0-beta10 (pre-release)

This is a **pre-release** build for testing, not a statement of production readiness or licence
compliance.

## What is in this build

- **Preet Patel (`@_preert_`) is now credited in the app.** He appears as a third profile card,
  alongside the original idea and Mehul, in both the **About** tab and the **startup welcome
  screen**, labelled **Lead Developer**. The card opens his Instagram profile, exactly like the other
  two, and is backed by a new avatar at `res/drawable-nodpi/ig_preet.jpg`.
- **The startup welcome screen now links to the Mhirex website** (https://mhirex.vercel.app). The
  About tab has had a **Visit Website** action since `v1.0-beta9`, but the popup, which is the first
  thing a new user sees, did not — the site was only reachable after finding the About tab. Both
  buttons point at the same `Branding.WEBSITE_URL`, so there is one URL to change, not two.
- **The GitHub star card is gone from the startup welcome screen.** It was the only item there that
  asked for something rather than telling you who made the app. The About tab's **Star** button is
  unchanged, so the repository is still one tap away.
- **Gujarati coverage for the About and welcome screens is now complete**, and this fixes a real gap:
  `str_visit_website` — the label on the About screen's **Visit Website** button — existed only in
  English, so a Gujarati device saw that button in English while the rest of the screen was
  translated. The four new `str_about_preet_*` strings and the two website strings are in Gujarati
  too. The 17 other translations still fall back to English for the About and welcome strings, as
  they always have.
- **The signing certificate is now recorded permanently, and checked.** See below.
- Release APKs are signed with the project release key.

## Signing certificate: recorded, and now enforced

`docs/signing-fingerprints.md` holds the permanent record of the release and debug certificates —
SHA-1 and SHA-256, subject, and which keystore produced them — so those values no longer have to be
re-derived by hand. The fingerprints are not secrets; every one of them is embedded in the public
APK. The keystore *password* is still never written to the repository, to a file, or to a command
line.

`tools/check-signing-fingerprint.sh` reads that record and compares a certificate against it:

```
./tools/check-signing-fingerprint.sh --print                     # the values, no keystore needed
./tools/check-signing-fingerprint.sh                             # check mhirex-release.jks
./tools/check-signing-fingerprint.sh --apk dist/v1.0-beta10/Mhirex-arm64-v8a.apk
```

It exits non-zero on a mismatch, and `tools/sign-release.sh` calls it, so a release signed by a
certificate other than the recorded one is now **refused rather than staged**. Previously
`sign-release.sh` printed the digest next to the advice that it "must match earlier releases" while
having nothing on disk to match it against.

The reason this matters: Google matches an app by **package name plus signing-certificate SHA-1**,
and Android can only upgrade an install signed by the same key. A regenerated keystore would
therefore break both at once, silently, for users.

## Sign-in: unchanged, and still not fixed here

`v1.0-beta9` rewrote the sign-in flow. **Nothing in this release changes it, and it is still not
verified.** The blocking issue is console registration, which cannot be done from this repository.
The two SHA-1s are in `docs/signing-fingerprints.md`; the release one must be added to **both** the
Android OAuth client and the Web OAuth client
`444731751675-28prvlfdjuhshvn0shmebbpb02e03not.apps.googleusercontent.com`.

`app/google-services.json` is not evidence either way: it records no `certificate_hash` entries at
all and lists only a Web OAuth client (`client_type: 3`), with no Android client (`client_type: 1`),
so it is hand-authored rather than a genuine Firebase export.

To diagnose, tap **Sign in with Google** and run alongside it:

```
adb logcat -c && adb logcat -s Auth.Api.Credentials
```

`UNREGISTERED_ON_API_CONSOLE` or `DEVELOPER_ERROR` means the certificate is not registered. That is
a console fix, not a code fix. Note that the app shows **no error at all** when this happens, because
Play Services reports it as a cancellation indistinguishable from the user dismissing the chooser.

## Known limitations in this build

- **Sign-in is not verified in the published build, and sign-out is not verified at all.** Nothing
  in this release touches that. `clearCredentialState()` and avatar deletion — the path that removes
  a personal photo from disk — have never been exercised. Try sign-out before relying on it.
- **The new avatar has not been reviewed by eye.** The supplied image is a high-contrast mark on a
  black field, not a portrait, so in the circular 48–54dp avatar frame it reads very differently from
  the two photographic avatars beside it. It has not been checked on a device by a person, only
  confirmed to decode and to be correctly wired up. Say the word if a different image was intended.
- **The new Gujarati strings have not been reviewed by a native speaker**, and were not contributed
  externally the way the rest of the Gujarati translation was. Treat them as a first draft.
- **The home-screen launcher icon is still the old one**, unchanged since `v1.0-beta8`. Themed
  (monochrome) icons remain dead code: `AndroidManifest.xml` points `android:icon` at the flat raster
  `@mipmap/logo`, so `mipmap-anydpi-v26/ic_launcher.xml` never resolves. Corrected adaptive-icon
  layers are committed; enabling them is a one-line manifest change.
- **Removing the star card leaves `res/drawable/bg_github_glass` unreferenced.** It was only used by
  that card and is now dead weight in the APK. Left in place rather than deleted, in case the card
  comes back.
- **17 translations still fall back to English** for the About and welcome-screen strings, including
  the four new `str_about_preet_*` ones. Gujarati is the only non-English locale that carries them.
- Device testing has only been run on an **API 36** emulator. API 29, 33 and 34 are not verified.
- The bundled `filter_preview_*.jpg` and `trans_preview_*.webp` assets still have no documented
  provenance, and neither does the new `ig_preet.jpg`.

## Upgrading

Per-ABI version codes are `base + 0/1/2` for `armeabi-v7a` / `arm64-v8a` / `x86_64`, and this
release raises the base from 11 to 14, giving **14 / 15 / 16** against `v1.0-beta9`'s 11 / 12 / 13.
The jump is deliberately larger than one: a base bump of 1 would have left `armeabi-v7a` installs on
a version code no higher than the one they already had, which Android refuses as an upgrade.

## Licence and source availability — still incomplete

Unchanged from `v1.0-beta8` and `v1.0-beta9`. Mhirex bundles `ffmpeg-kit-full-gpl`, which is licensed
under GPL-3.0. **The GPL disclosure work is not complete.** The in-app AboutLibraries entry, the
packaged GPL licence text and the corresponding-source offer still need to be added.

This release therefore **does not claim to be GPL-compliant**, and must not be represented as
satisfying GPL distribution obligations. Those obligations need to be completed before a public or
Play Store distribution. LibreCuts/MIT attribution from the upstream project is retained in the app
and repository.
